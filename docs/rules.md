# 裁决规则

> 一句话：**只处理「四码 ∧ 全是汉字 ∧ 至少一个单字」的码，每种码只留一条候选。**

## 输入

| 来源 | 文件 | 作用 |
| :--- | :--- | :--- |
| 主词库 | `flypy.table.bin` → 反编译 | 157,452 条，方案的骨架 |
| top | `flypy_top.txt` | 置顶词 |
| sys | `flypy_sys.txt` | 符号表 / 二重简码 |
| user | `flypy_user.txt` | 用户词 |
| full | `flypy_full*.txt` | 「全码字补全表」（可选） |

所有来源先合并成 `码 → 候选列表`，同码同文本去重（保留先出现的来源）。

## 分类

对每个长度为 4 的码：

```
候选数 == 1                    → 不动
含符号 / emoji / 外文           → 不动（91 个）
全是汉字但没有单字              → 不动（1,179 个）
全是汉字且至少一个单字          → 裁决（2,106 个）
```

「汉字」的判定：CJK 基本区 + 扩展 A + 兼容区 + 扩展 B 及以后 + 中文标点（一句话词条里会有逗号）。

## 排序（取最小者）

| 优先级 | 键 | 值 |
| ---: | :--- | :--- |
| 1 | 是否单字 | 词 = 999（永远输），字 = 0 |
| 2 | 《通用规范汉字表》等级 | 1 / 2 / 3；表里没有 = 99 |
| 3 | 有无更短的码 | 该字在别的码里的最短长度；没有 = 99 |
| 4 | 来源优先级 | main 0 < top 1 < sys 2 < user 3 < full 4 |
| 5 | 文件内顺序 | 越小越优先 |

第 2 项需要 `--levels` 指向一个「字符 → 等级」的 JSON（例：`[{"character":"一","level":"1",...}, ...]`）。
**不提供也能跑**，此时退化为「有无更短码 + 来源 + 顺序」，生僻字和常用字区分不了。

## 输家

全部降级到 `code[:3]`：

- 不删除、不合并、不去重（除非三码已有同名条目）
- 追加到词库末尾，不改变三码原有顺序
- `xxx'` 这类「三字母 + 隔音符」的码，`code[:3]` 会落在三字母上

## 确定性

同一份输入 + 同一份等级表 → 逐字节相同的输出。没有随机、没有时间戳、没有「当前词频」。

```bash
python3 flypy4.py ... --out a
python3 flypy4.py ... --out b
diff -r a b      # 必须为空
```

## 它**不**做的事

- 不改三码及以下的任何码（只往后追加）
- 不动符号表里的四码
- 不动「没有单字」的四码（那是词库本来的样子）
- 不改 schema 的引擎配置、不改 librime
- 不生成 emoji、不做简繁转换、不碰用户词库

## 边界情况

| 情况 | 行为 |
| :--- | :--- |
| 四码的赢家只存在于 sys/top/user/full | 搬进主词库（否则停用 full 后会丢） |
| 四码只有一条候选、且只由 full 提供 | 搬进主词库（14 个，如 `vyav → 屯`） |
| 输家的三码已存在同名条目 | 跳过（不产生重复行） |
| 隔音符码 + `--apostrophe keep` | 完全不碰 |
| 等级表缺字 | 等级 99，靠后面几项决胜 |
| 同码同字不同来源 | 去重，保留先出现的来源 |
