# flypy-4code-single-char

**小鹤音形 · 四码必上屏 · 上屏必单字**

官方这套词库，从配置到数据都是傻逼行为：它把「四码上屏」写进配置，然后在 3,376 个码上做不到（不开补全表也有 2,522 个）。

---

## 装（三行）

```bash
git clone https://github.com/starlifezzz/flypy-4code-single-char.git
cd flypy-4code-single-char
./tools/install.sh --rime ~/.local/share/fcitx5/rime
```

然后 **托盘右键 → 部署**（或 `systemctl --user restart 'app-org.fcitx.Fcitx5@autostart.service'`）。

装完直接试 —— 敲完四下停手，**不用按空格**：

```
qrrw → 全        bnmm → 骉        aifu → 挨        yivv → 已
```

回滚（脚本会把备份路径打在屏幕上）：

```bash
cp -a ~/rime-backup-YYYYmmdd-HHMMSS/. ~/.local/share/fcitx5/rime/
```

> ⚠️ 只还原 bin、不删 `flypy.dict.yaml` 是没用的 —— 下次部署会再覆盖回去。

## 效果

**该出字的四码一共 2,106 个：官方 210 个敲完还要选，启用补全表后 2,106 个全要选，本方案 0 个。**

| 状态 | 这 2,106 个里还要二次选择的 |
| :--- | ---: |
| 官方默认（没启用「补全表」、关 emoji） | 210（10.0%） |
| 官方**让你启用**「全码字补全表」之后 | **2,106（100%）** |
| **本方案** | **0** |

全量口径（63,534 个四码，librime 1.17.0 逐码回放按键实测）：

| 状态 | 四码敲完还要再选一次的码 | 占比 |
| :--- | ---: | ---: |
| 官方默认（没启用「补全表」） | 2,522 | 3.97% |
| 官方默认 + 关掉 emoji 联想 | 1,480 | 2.33% |
| 官方**让你启用**「全码字补全表」之后 | 4,382 | 6.90% |
| 上面 + 关掉 emoji | **3,376** | **5.31%** |
| **本方案** | **1,270** | **2.00%** |

**剩下的 1,270 不是「没解决干净」，是四码位本来就还装着别的东西：**

- **1,179 个**：码上只有两个词，一个字都没有 —— `hyys` = 昏庸 / 和颜悦色，`dusi` = 堵死 / 毒死。词是四码的合法住户，官方从来没给这些码配过字
- **91 个**：`o` 打头的符号 / emoji 码 —— `oibf` = 🙇‍♂️ / 🙇‍♀️ / 💯

把这两类算成「没解决」，等于要求「四码只出字」。那不是形码，本方案一开始就不打算做。

## 官方词库烂在哪

**官方这套词库，从配置到数据都是狗操的傻逼行为。**

妈逼的，音形，现在成什么脑瘫玩意。出简让全，让个jb啊。老子本来就是为了四码上屏，现在不光要空格，还有选择 —— 操你妈大血屄。

**1. 配置写着自动上屏，数据当场拉稀。**

```yaml
max_code_length: 4    # 全码码长，过则顶字上屏
auto_select: true     # 自动上屏
auto_select_pattern: ^;.$|^\w{4}$
```

`^\w{4}$`，四键上屏。然后它配套的数据让这句话在最烂状态下于 5.31% 的码上失效。**说它脑瘫都是夸它 —— 脑瘫至少不会写注释说自己要上屏，然后把数据做成不上屏。**

**2. `flypy_full全码字.txt`：一个叫「补全」的傻逼文件，干的是倒垃圾。**

2,152 条里 **1,684 条（78.3%）的字本来就有 ≤3 码**。它补的不是缺失，是重复。启用后重码从 1,480 涨到 3,376（**+128%**）：

```
3,376 = 1,179（本来就没单字）+ 91（符号）+ 2,106（含单字的四码，全灭）
```

**一个 2,152 条的文件，1,684 条是废的。** 搁别的项目，这种提交早被骂到删库跑路了；在小鹤这儿，它进了正式发行包，还配了说明书。

**3. 它知道会重码，然后决定让补进来的字去死。**

```yaml
custom_phraseQMZ:
  initial_quality: -1  #和系统词重码时居后
```

`-1` = 补进来的字永远排在原有的词后面。结果是：你本来一按就上屏的位置变成了菜单，而菜单里那条字你永远不会选。**字没补上，顶屏没了。这不是失误，这是缺德。**

**4. 启用方式：改文件名。**

没有开关，没有警告，没有「删了会怎样」。一个能一键废掉整个方案的补丁，安装方式 = 重命名文件。这是 2026 年，不是 2006 年。

**5. 主词库是二进制，157,452 条，零注释。**

核心数据编译成 bin 丢给你，然后让你调 `initial_quality` 这种整数字段过日子。**这不叫方案，这他妈叫黑箱。**

**6. emoji 默认开着，专挑你唯一的候选下手。**

1,069 个四码的唯一候选在 emoji 表里都有对应项：`爸爸` → `爸爸` + `👨🏻`，两候选，顶屏没了。同一份数据单纯关掉 emoji，需要选的码减少 **1,042** 个。

**一坨狗屎摆在那儿，还生怕你没踩到，默认给你打开。**

**7. 两个包两个版本号（10.26.9 / 10.26.11），没有 changelog。**

改了什么？不知道。**这不是版本管理，这是把用户当傻缺，还是不发工资那种。**

## 裁决规则

只对「四码 ∧ 全是汉字 ∧ 至少一个单字」的码动手（2,106 个）。排序取最小者：

| 优先级 | 键 | 说明 |
| ---: | :--- | :--- |
| 1 | 是否单字 | **词无条件输给字** |
| 2 | 《通用规范汉字表》等级 | 1 常用 / 2 次常用 / 3 生僻（缺表时全部同级） |
| 3 | 有无更短的码 | 已经有 2/3 码的字，不该霸着四码 |
| 4 | 来源优先级 | 主词库 > top > sys > user > full |
| 5 | 原文件顺序 | 都不相同时先出现的赢 |

输家 **2,411 条 → 降级到三码 2,311 条，一条不删**。离开四码的 2,425 条（838 字 + 1,587 词）**0 条丢失**，其中 1,206 条（76%）落在三码前两位（空格 / `;`），击键数仍是四下。

完整规则与边界情况见 [docs/rules.md](docs/rules.md)。

## 为什么不直接改 bin

bin 是编译缓存，不是数据源。用户目录里只要有 `*.dict.yaml`，部署就会重新编译覆盖它 —— 实测：

```
flypy.dict.yaml        18:16:23
build/flypy.table.bin  18:16:47     ← 24 秒后自己编译出来了
```

所以流程是：官方 bin → 反编译 → 裁决 → 重新编译。和手改 bin 是同一件事，只是**可 diff、可复现、可回滚**。机制与证据见 [docs/mechanism.md](docs/mechanism.md)。

## 已知局限

1. **1,270 个码仍要选，但没有一个是「该出字却出不了字」的** —— 1,179 个码上只有词，91 个是符号 / emoji 码。裁决它们等于「四码出词」，那就不是形码了。
2. **`xxx'` 这类 73 个码默认也被裁决**（97 条）。它们本来就不会自动上屏，想保留原样：`--apostrophe keep`。
3. **裁决依据是等级 + 简码长度，不是真词频**，个别地方可能和直觉不符。
4. **官方更新后必须重跑** —— 只要 `flypy.dict.yaml` 在，官方新 bin 就永久失效。这是本方案唯一会累积的债。
5. **仓库不含任何词库数据**（见下）。

---

## 为什么仓库里没有词库

小鹤只发编译好的 `flypy.table.bin`，包里没有任何再分发许可。把 159,674 条词库贴到公开仓库 = 二次分发别人的数据，还可能被下架。

所以本仓库只有代码：**输入是你自己那份官方包，输出才是裁决结果。** 顺便也就永远跟着最新版词库走。

---

## 这不是给谁的

如果你觉得「四码出词也挺好啊」——那你要的不是形码，是拼音。Rime 自带 `double_pinyin_flypy`，去用那个。

形码的全部价值是**确定性**：敲完四下，出来那一个字，不用看屏幕。官方把这份确定性卖出去了 3,376 次，本仓库买回来 2,106 次。
