# flypy-4code-single-char

**小鹤音形（flypy）· 四码必上屏 · 上屏必单字**

官方词库做不到的事，这里用一个 290 行的 Python 脚本做到了。

> 下面每一句脏话都挂着一个能复现的数字。
> 骂得再难听，也是事实 —— 不信就照最后一节自己跑。
>
> 骂的是**这份词库和这套配置**，不是人。作者名字我一个字都不提。

## 三十秒，先看官方交出来的东西烂成什么样

| 状态 | 四码敲完还得再按空格挑一次的码 | 占比 |
| :--- | ---: | ---: |
| 官方默认（没敢启用「补全表」） | 2,522 | 3.97% |
| 官方默认 + 关掉那破 emoji 联想 | 1,480 | 2.33% |
| 官方**让你启用**「全码字补全表」之后 | 4,382 | 6.90% |
| 上面 + 关掉 emoji | **3,376** | **5.31%** |
| **本方案** | **1,270** | **2.00%** |

（总样本 63,534 个四码，librime 1.17.0 逐码回放按键实测，复现命令在文末）

**说它脑瘫都是夸它。** 脑瘫至少不会写注释说自己要上屏，然后把数据做成不上屏。

而它的配置文件里白纸黑字写着：

```yaml
# flypy.schema.yaml（官方原版，一个字节没改）
speller:
  max_code_length: 4    # 全码码长，过则顶字上屏
  auto_select: true     # 自动上屏
  auto_select_pattern: ^;.$|^\w{4}$   # 自动上屏规则
```

`^\w{4}$`，四键，自动上屏。说得跟真的一样。

然后它配套的数据让这句话在最烂的状态下于 **5.31%** 的码上当场拉稀。

**这不是「有一点瑕疵」。**

这是一个输入法方案，在自己写进配置里的、最核心的那个承诺上，六分之一的时候做不到。

说难听点：**这玩意儿连自己吹的牛逼都兜不住，还他妈好意思叫「方案」。脑瘫到家了。**

## 一、`flypy_full全码字.txt`：一个叫「补全」的傻逼文件

官方说明书原话：

> full——<全码字>分类文件，需删除文件名中的「全码字」，再部署生效，**补全所有字全码**

听着像人话。实测这张表 2,152 条：

| | 条数 | 占比 |
| :--- | ---: | ---: |
| 那个字**本来就有 ≤3 码** | 1,684 | 78.3% |
| 那个字真的只有 4 码可打 | 468 | 21.7% |

**它补的不是缺失，是重复。** 一个标着「补全」的文件，五分之四的内容是把已经在简码里的字，重新塞回四码那条独木桥上。

结果呢？重码直接翻倍：

```
不启用补全表：1,480 个四码需要二次选择
启用补全表后：3,376 个四码需要二次选择     ← +128%
```

拆开看更难看：

```
3,376 = 1,179（本来就没单字，这个认）
      +    91（符号 / emoji 码）
      + 2,106（含单字的四码 —— 启用补全表后无一例外全成多候选）
```

**`flypy_full` 一启用，含单字的四码 100% 全灭，一个不剩。**

这不是补全，这是**往你必经之路上倒垃圾，然后跟你说「看，全了吧」**。

**一个 2,152 条的文件，1,684 条是废的。** 搁别的项目，这种提交早被骂到删库跑路了；在小鹤这儿，它进了正式发行包，还配了说明书。

（那 2,106 个里有 210 个在没启用补全表时就已经是二选一 —— 也就是说，官方主词库自己也没把这事做干净。它连「不装补丁」都做不对。**废物到什么程度呢：关掉补丁也烂，打开补丁更烂。**）

## 二、它自己知道会重码，然后决定让补进来的字去死

```yaml
# flypy.schema.yaml（官方原版）
custom_phraseQMZ:
  dictionary: ""
  user_dict: flypy_full
  db_class: stabledb
  enable_sentence: false
  enable_completion: false
  initial_quality: -1  #和系统词重码时居后
```

`-1`。**补进来的那个字，永远排在原有的词后面。**

所以这张垃圾表实际产生的作用是：

1. 你本来一按就上屏的位置 —— 变菜单了
2. 补进来的字在菜单里排最后 —— **你永远不会选它**
3. 字没补上，顶屏没了

「补全所有字全码」，补了个寂寞。**这是个负收益补丁，官方还写在说明书里推荐你启用。**

写这段配置的人不是不懂，他连注释都写了「和系统词重码时居后」—— 他知道会重码，也知道字会被挤下去，然后就这么发了。

**这不是失误，这是缺德。** 一个知道自己在制造垃圾、还把它写进说明书推荐你用的补丁，用「脑残」形容都算客气。

## 七、隔音符码和 `^\w{4}$` 天生互斥

`bic'`、`bnm'` 这种「三字母 + 隔音符」也占四个字符，但 `'` 不是 `\w`，所以得到的待遇是：**永远不会自动上屏**。

## 本方案做什么

**不是我要改，是它烂到不改没法用。**

**数据层裁决。不动引擎，不删数据，不碰 bin 的字节。**

| 情况 | 处理 |
| :--- | :--- |
| 四码只有一条候选 | 不动 |
| 四码含符号 / emoji / 外文（91 个） | 不动 |
| 四码全是汉字但没有单字（1,179 个） | **不动**（这是词库本来的样子） |
| 四码全是汉字且**有单字**（2,106 个） | **只留一个最常用的单字**，其余全部降级到三码 |
| 被降级的条目（2,411 条 → 落位 2,311 条） | 挪到 `code[:3]`，**一条不删** |

结果：

- 有单字的四码，**100% 只剩一个单字**，停手即上屏
- 剩下的 1,270 个码 = 1,179 个「本来就没单字」+ 91 个符号码，按设计原样保留
- 挪走的 2,425 条（838 字 + 1,587 词）**全部仍在三码可打出，0 条丢失**；其中 1,206 条（76% 的词）排在三码前两位（空格 / `;`），击键数仍是四下

### 例子

| 四码 | 官方（启用补全表） | 本方案 |
| :--- | :--- | :--- |
| `qrrw` | 全 / 佺 二选一 | **全**（佺 在 `qrr`） |
| `bnmm` | 表面 / 骉 二选一 | **骉**（表面 在 `bnm`） |
| `aifu` | 爱抚 / 挨 二选一 | **挨**（爱抚 在 `aif`） |
| `yivv` | 已 / 乙 二选一 | **已**（乙 在 `yiv`） |
| `ahqi` | 昂起 / 爱恨情仇 | 昂起 / 爱恨情仇（该码没有单字，**不动**） |

## 为什么不直接改 bin

**因为 bin 是编译缓存，不是数据源。改它等于往嘴里塞鼻涕。**

Rime 部署时，只要用户目录里有 `*.dict.yaml`，就会重新编译并覆盖 `build/*.bin`。实测时间戳：

```
flypy.dict.yaml        18:16:23   ← 把裁决后的词库放进用户目录
build/flypy.table.bin  18:16:47   ← 24 秒后，部署器自己编译出来了
```

所以流程是：

```
官方 flypy.table.bin（黑箱）
      │  rime_table_decompiler
      ▼
  157,452 行文本
      │  flypy4.py（本仓库）
      ▼
  flypy.dict.yaml —— 重新编译 → 新的 flypy.table.bin
```

和「十六进制编辑器手改 bin」是同一件事，只是**可 diff、可复现、可回滚**。

细节见 [docs/mechanism.md](docs/mechanism.md)。

## 用

### 0. 依赖

- Python 3.10+
- `librime` 的 `rime_table_decompiler`（验证另需头文件 + `rime_deployer`）

```bash
nix profile install nixpkgs#librime
```

### 1. 一键

```bash
git clone <本仓库地址>
cd flypy-4code-single-char
./tools/install.sh --rime ~/.local/share/fcitx5/rime
```

它会：备份你的整个 Rime 用户目录 → 反编译官方 bin → 裁决 → 写回 `flypy.dict.yaml` / `flypy_sys.txt` → 从 schema 里摘掉 `custom_phraseQMZ` → 停用 `flypy_full*.txt` → 关掉 emoji 联想 → 打印下一步。

然后**托盘右键 → 部署**（脚本不会替你部署）。

### 2. 手动

```bash
RIME=~/.local/share/fcitx5/rime

./tools/decompile.sh "$RIME/build/flypy.table.bin" /tmp/flypy.yaml

python3 flypy4.py \
  --decompiled /tmp/flypy.yaml \
  --rime "$RIME" \
  --levels /path/to/flypy_n.json \
  --out ./out

cp out/flypy.dict.yaml out/flypy_sys.txt "$RIME"/
```

### 3. schema 必须改两处

```diff
   translators:
     - table_translator@custom_phraseYH
-    - table_translator@custom_phraseQMZ
     - reverse_lookup_translator
@@
-custom_phraseQMZ:
-  dictionary: ""
-  user_dict: flypy_full
-  db_class: stabledb
-  enable_sentence: false
-  enable_completion: false
-  initial_quality: -1 #和系统词重码时居后
-
```

（`tools/patch-schema.py` 会做这件事，幂等）

### 4. emoji 联想必须关

`flypy.custom.yaml`：

```yaml
patch:
  switches/@next:
    name: emoji_suggestion
    reset: 0          # ← 0 = 关
    states: [ "🈚︎", "🈶️" ]
```

完整可用版本见 [examples/flypy.custom.yaml](examples/flypy.custom.yaml)。

## 裁决规则

只对「四码 ∧ 全是汉字 ∧ 至少一个单字」的码动手。排序取最小者：

| 优先级 | 键 | 说明 |
| ---: | :--- | :--- |
| 1 | 是否单字 | **词无条件输给字** |
| 2 | 《通用规范汉字表》等级 | 1 = 常用，2 = 次常用，3 = 生僻（缺表时全部同级） |
| 3 | 有无更短的码 | 已经有 2/3 码的字，不该霸着四码 |
| 4 | 来源优先级 | 主词库 > top > sys > user > full |
| 5 | 原文件顺序 | 都不相同时，先出现的赢 |

输家降级到 `code[:3]`，不去重、不删除、不合并。

完整规则与边界情况见 [docs/rules.md](docs/rules.md)。

## 已知局限（老实说，不装）

1. **1,270 个码仍然需要选。** 其中 1,179 个是该码本来就没有单字 —— 按设计不动。把它们也裁决掉，等于「四码出词」，那就不是形码了。
2. **`xxx'` 这类 73 个码默认也被裁决**（97 条）。它们本来就不会自动上屏。想保持原样：
   `python3 flypy4.py --apostrophe keep ...`
3. **裁决依据是等级 + 简码长度，不是真词频。** 个别地方可能和你的直觉不符，只能靠改脚本加白名单。
4. **官方更新后必须重跑。** 一旦有了 `flypy.dict.yaml`，官方的 `build/flypy.table.bin` 就永久失效 —— 新版词库拷进来不会有任何效果。这是本方案唯一会随时间累积的债。
5. **本仓库不含任何词库数据。** 全部由你自己的官方包现场生成。

## 这不是给谁的

如果你觉得「四码出词也挺好啊」——那你要的不是形码，是拼音。Rime 自带 `double_pinyin_flypy`，去用那个，别用这个。

形码的全部价值是**确定性**：敲完四下，出来那一个字，不用看屏幕。

官方把这份确定性卖出去了 3,376 次（启用补全表时）。本仓库把它买回来 2,106 次。
